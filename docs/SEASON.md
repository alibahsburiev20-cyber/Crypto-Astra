# Сезон: правила, рейтинг и закрытие

Основание: спецификация 2.1, §II.10 (сезоны) и §II.6 (задачи `season_close`,
`snapshot_export`), часть V (гейт 3). Числа — из `worker/src/shared/constants.ts`,
код — `worker/src/world/modules/season.ts`.

## Зачем сезон

Сезон — причина вернуться. Восемь недель задают горизонт: очки сгорают, рейтинг
обнуляется, у всех снова равные шансы. Без этого очки копились бы вечно и ничего
не значили, а «прокачка» превращалась бы в бесконечную лестницу.

## Рамки

| Что | Значение |
|---|---|
| Длина сезона | **56 дней** (8 недель), `SEASON_DAYS` |
| Начало первого сезона | момент создания мира |
| Следующий сезон | начинается сразу после закрытия предыдущего |
| Пропущенные сезоны | не догоняются: новый стартует «сейчас», призы за пустые сезоны не платятся |
| Идентификатор | `s1`, `s2`, … по номеру |

Сезон живёт в таблице `seasons` мира. Активный всегда один (`status = 'active'`),
история закрытых остаётся в той же таблице.

## Очки

- Очки начисляются **только за рейсы** (`expedition_reward`) и лежат в Ledger как
  актив `points`.
- Дневные ограничители прежние: `POINTS_SOFT_CAP = 700` (дальше очки режутся
  вдвое), `POINTS_HARD_CAP = 1000` в сутки.
- Очки нельзя купить, передать, получить за рекламу или за деньги.
- Баланс «Очки» в кошельке — это очки **текущего** сезона: при закрытии они
  списываются записью `season_reset`.

## Рейтинг

Порядок сортировки: **очки → опыт → дата регистрации → id**. Тай-брейк нужен,
чтобы при равенстве очков место не прыгало между запросами.

- В рейтинг попадают все игроки мира, включая тех, у кого 0 очков.
- На экране сезона — топ-20 (`SEASON_TOP_LIMIT`) и своё место.
- Подпись игрока — «Пилот A1B2C3» из первых шести символов id. Email и прочие
  данные аккаунта мир не знает и в рейтинг не попадают.

## Награды

| Место | Награда |
|---|---|
| 1 | 2 000 ASTRA |
| 2 | 1 200 ASTRA |
| 3 | 800 ASTRA |
| 4–10 | 400 ASTRA |
| остальные, у кого есть очки | 150 ASTRA |
| 0 очков | ничего |

Награда начисляется один раз, записью `season_reward` с `source_ref = "<сезон>:<место>"`.
Призы — это выпуск ASTRA, поэтому они малы: 2 000 ASTRA — примерно четыре дня
активной игры. Симуляция 8 недель на 200 игроках: призы дают **1.7 %** выпуска и
снижают поглощение с 83.2 % до **81.8 %** — остаётся в цели 70–90 %
(`docs/ECONOMY.md`).

## Закрытие

1. Задача `season_close` ставится на `ends_at` сезона сразу при его создании.
2. В момент `ends_at` мир считает итоговый рейтинг и пишет `season_results`
   (место, очки, уровень, опыт, приз) — это единственное место, где рейтинг
   закрытого сезона хранится целиком.
3. Призы начисляются через Ledger, очки списываются записью `season_reset`.
4. Сезон получает `status = 'closed'`, `closed_at`, число игроков и сумму очков.
5. Сразу создаётся следующий сезон, начинающийся с конца предыдущего.
6. Снимается снимок мира `kind = 'season_close'` — он уедет в архив (D1/R2).

**Замороженный мир призы не получает.** Если сверка не сошлась, задача
переносится на час: сначала журнал, потом деньги. Это тот же принцип, что и
`423 world_frozen` для игровых действий.

**Повторное закрытие ничего не делает.** Задача может сработать дважды; второй
вызов видит `status = 'closed'` и выходит, не начисляя призы.

## Архив и восстановление

| Что | Где |
|---|---|
| Снимки мира (недельные и при закрытии) | мир `season_snapshots` → cron → R2 или D1 `world_snapshots` |
| Итоги закрытых сезонов | D1 `season_history` |
| Полный журнал | Ledger мира (append-only) + Time Travel Durable Objects |

Без бакета R2 снимки складываются в D1 (payload в `world_snapshots`). Ключ в R2:
`worlds/<мир>/snapshots/<kind>-<created_at>-<id>.json`.

Проверка архива:

```bash
npm run verify-snapshot -- --file snapshot.json --sha256 <hash из D1>
```

Скрипт проверяет версию формата, неотрицательность сумм, согласованность головы
хеш-цепочки с числом строк и то, что призы в итогах совпадают с таблицей наград.
Восстановление — по `docs/RUNBOOK_BACKUP.md`.

## Что видит клиент

- `/me` → компактный `season`: номер, рамки, дни до конца, очки, место, число игроков.
- `GET /season` → полный отчёт: сезон, своё место и приз, топ-20, таблица наград,
  до трёх прошлых сезонов с победителем и своим местом.
- Раздел «Сезон» в боковом меню и доке; на мостике — карточка с местом и таймером.

## Антифрод

- Очки меняет только сервер и только в начислении награды рейса.
- Клиент не передаёт ни очков, ни места: все значения считаются из Ledger.
- Повтор задачи закрытия идемпотентен по статусу сезона.
- Призы и обнуление — две отдельные записи журнала, обе видны игроку в «Журнале».
