# Astra Pool: учёт и публичный отчёт (этап 5, срезы 5.1–5.2)

Пул — это **деньги вокруг игры**: взносы, призы и расходы на операции. Он не связан
с игровой валютой: ASTRA живёт в Ledger мира, её нельзя купить, продать или вывести,
и на отчёт пула она не влияет. Пока выплат нет вообще — флаг `payoutsEnabled`
в коде и в отчёте выключен до гейта 4.

## Что сделано

| Срез | Содержание | Где |
|---|---|---|
| 5.1 Учёт | таблица `pool_entries` в D1, append-only, уникальный `ref`, резерв 20 % на операции, отчёт по валютам | `worker/migrations/d1/0006_pool.sql`, `worker/src/pool/accounting.ts` |
| 5.2 Отчёт | публичная страница `/pool.html` и JSON `/pool.json`, без входа и без персональных данных | `client/pool.html`, `client/pool.js`, `worker/src/routes/pool.ts` |

## Правила учёта

- **Одна запись — одна операция.** `kind`:
  - `in` — взнос в пул;
  - `out` — выплата приза;
  - `ops` — расход на операции (домен, хостинг, реклама, работа).
- **Суммы в минимальных единицах валюты** (для EUR и USD — центы), целым числом.
  Float в деньгах не используется нигде.
- **Валюты:** `EUR`, `USD`. Пул не складывает валюты в одно число — это было бы
  враньём без курса; отчёт показывает итог по каждой отдельно.
- **Резерв 20 %** (`POOL_FEE_BP = 2000`) от взносов считается призовым фондом
  отдельно от «остатка на счетах». Это отчётная величина, а не автоперевод.
- **Append-only.** `UPDATE` и `DELETE` запрещены триггерами. Исправление — новая
  запись с обратным смыслом и пояснением, а не правка истории.
- **`ref` уникален** — номер платежа у провайдера. Повторный вебхук вернёт
  `pool_ref_exists` и не удвоит суммы.
- **Заметка публична**: она попадает на `/pool.html`. Имена, адреса и реквизиты
  писать нельзя — только пояснение вида «взнос участника за март».

## API

| Метод | Путь | Доступ | Что отдаёт |
|---|---|---|---|
| GET | `/pool.json` | публично | итоги по валютам, последние 10 операций без `ref` и `id`, флаг выплат |
| GET | `/pool/report` | публично | то же (алиас для удобства мониторинга) |
| GET | `/admin/pool` | токен | все записи с `ref` и `id` для сверки с выпиской |
| POST | `/admin/pool/entry` | токен | добавляет запись |

Запись принимает JSON:

```json
{ "kind": "in", "amount": 4900, "currency": "EUR", "ref": "pay_2026_03_001", "note": "взнос участника за март" }
```

`amount` — целое число минимальных единиц (4900 = 49,00 EUR). Ошибки: `bad_pool_kind`,
`bad_pool_amount`, `bad_pool_currency`, `bad_pool_ref`, `pool_ref_exists` (409),
`admin_token_required` (401), `admin_forbidden` (403), `admin_disabled` (503),
`pool_unavailable` (503).

### Как включить запись без терминала

1. Cloudflare Dashboard → Workers & Pages → **crypto-astra** → Settings →
   Variables and Secrets → **Add** → тип **Secret**, имя `ADMIN_TOKEN`,
   значение — длинная случайная строка. Deploy не нужен: секрет применяется к
   следующему запросу.
2. Открыть `https://crypto-astra.cryptoastra.workers.dev/pool.html`, затем
   DevTools → Console и выполнить (подставив свой токен и номер платежа):

```js
await fetch('/admin/pool/entry', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', 'X-Admin-Token': 'СЕКРЕТ' },
  body: JSON.stringify({ kind: 'in', amount: 4900, currency: 'EUR', ref: 'pay-001', note: 'взнос за март' }),
}).then((r) => r.json());
```

Пока админки нет (срез 5.3), это единственный путь — он работает из браузера и не
требует терминала. Токен нигде не сохраняется: он живёт только в этом запросе.

## Публичная страница

`/pool.html` — статический HTML (поисковик и рекламная сеть видят текст без JS) плюс
`/pool.js`, который забирает `/pool.json` и только форматирует числа. Своих расчётов
в браузере нет: подменить суммы в консоли бессмысленно, отчёт пересобирается на
сервере из append-only таблицы.

Что видно: взносы, резерв 20 %, призовой фонд, выплаченные призы, расходы на
операции, остаток; последние операции; правила и дисклеймер. Чего нет и не будет:
обещаний прибыли, «гарантированного дохода», курса ASTRA к деньгам.

Ссылки на страницу: пункт «Astra Pool · отчёт» в боковом меню игры и ссылка
«Прозрачность пула» в футере лендинга.

## Схема и миграции

Канон — `worker/migrations/d1/0006_pool.sql`. Но деплой идёт из браузера через
Cloudflare Workers Builds, а `wrangler d1 migrations apply --remote` оттуда не
запустить, поэтому таблицы идемпотентно создаются и при первом обращении
(`worker/src/db/bootstrap.ts`). На мигрированной базе это no-op; на новой — база
поднимается сама. Тем же способом самолечатся таблицы архива этапа 3
(`season_history`, `world_snapshots`) — их создаёт cron перед первой выгрузкой.

Триггеры append-only создаются отдельными запросами: если D1 не даст их создать,
учёт продолжит работать, но append-only будет держаться только кодом (в лог уйдёт
предупреждение).

## Призовой фонд из выручки (2026-11-23)

Отдельно от взносов: **`POOL_PRIZE_SHARE`** (по умолчанию 40 %) от каждой покупки
в магазине начисляется в `pay_pool_cycles.prize_budget` текущего цикла.

- деньги в фонд приходят **только из наших продаж косметики**;
- взносов игроков нет: `confirmed_in` от покупок не меняется;
- начисление идёт одной транзакцией с записью журнала, поэтому повтор того же
  заказа (тот же `Idempotency-Key`) фонд не удваивает;
- сумму видно в `GET /admin/pay` → `pool.prizeBudget` / `prizeBudgetText`.

Зачем именно так: «пул, куда люди вкладывают деньги в расчёте на выплаты» — это
инвестиционная схема с лицензией и уголовным риском при выплатах из новых
взносов. Призовой фонд из собственной выручки — это расход на маркетинг, а не
приём вкладов. Правила сезона (кто и за что получает приз) публикуются до старта.
