# Гейт 1: сверка Ledger семь дней

Гейт закрывается, когда **семь дней подряд** ежедневная сверка проходит без расхождений.
Это не задача про код: ежедневная проверка (`ledger_verify`) давно стоит в планировщике
мира, а с 18.11.2026 её результат виден снаружи — в ответе `/me` появился блок:

```json
"verify": { "at": 1794993173229, "ok": true }
```

`at` — время последней сверки (мс, серверные часы), `ok` — сошлась ли хеш-цепочка и
балансы. Пока сверка ни разу не проходила, там `{ "at": null, "ok": null }`.

## Счётчик ведётся сам

С 18.11.2026 сервер хранит историю сверок по дням (таблица `ledger_checks` в мире) и
считает стрик — сколько **дней подряд** сверка проходила без расхождений. Это поле
`verify.streak` в ответе `/me`:

```json
"verify": { "at": 1794993173229, "ok": true, "streak": 3 }
```

Клиент показывает его в разделе **«Журнал»**: «Сверка журнала: OK · N ч назад.
3/7 дней до гейта 1.» На седьмом дне — «7/7 дней — гейт 1 закрыт.»

Правила подсчёта, чтобы не было споров:

- Если сегодняшняя сверка ещё не прошла (она идёт раз в сутки), счёт считается со
  вчерашнего дня — иначе стрик обнулялся бы каждую полночь.
- Пропущенный день обнуляет счёт.
- Одна сверка с `ok: false` обнуляет счёт и замораживает мир.
- Повторная сверка в тот же день стрик не накручивает.

Ручная таблица ниже остаётся только как место для заметок.

Сверка идёт раз в сутки и ставится в очередь при создании мира; первый прогон —
через 5 минут после появления первого игрока. Если мир пустой и никто не заходил,
задачи всё равно отрабатывают по alarm.

## Что делать при `ok: false`

1. Мир замораживается автоматически: все игровые действия отвечают `423 world_frozen`.
2. Снять снимок мира (Durable Object SQL) и прогнать
   `npm run check-ledger -- --file snapshot.json`.
3. Найти первый `seq`, где цепочка расходится; починить причину, выкатить.
4. Разморозка — только успешной сверкой. Счётчик семи дней начинается заново.
