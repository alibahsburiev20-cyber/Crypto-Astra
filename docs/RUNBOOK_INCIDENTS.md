# Инциденты

## Мир заморожен (`world_frozen`, 423)

Признак: игроки получают 423, в `meta` `frozen = 1`, `last_verify_ok = 0`.

1. Не размораживать вручную и не править Ledger.
2. Снять снимок мира, прогнать `npm run check-ledger -- --file snapshot.json`.
3. Найти первый `seq` с ошибкой. Проверить `frozen_seq` в `meta`.
4. Сверить с логами Worker: `job failed`, `unhandled`, деплой перед инцидентом.
5. Если ошибка в коде — исправить, выкатить. Следующая `ledger_verify` разморозит
   мир только при успешной сверке. Если данные повреждены — восстановление по
   `RUNBOOK_BACKUP.md`.

## Задача `failed`

Признак: в `jobs` строка `status = 'failed'`, `attempts >= 5`.

1. Найти `kind` и `payload`, посмотреть лог `job failed <kind> <error>`.
2. Проверить, не начислена ли уже награда (экспедиция `completed`).
3. Исправить причину, вернуть задачу в `pending` с `run_at` в будущем.
4. Не запускать повторно `expedition_finish` без проверки статуса рейса — обработчик
   сам идемпотентен по статусу, но лучше убедиться.

## Нет свободных мест (`world_full`)

1. Проверить `WorldLobby.seats()` и `world_seats`.
2. Если лобби недоступно, регистрация отвечает 409; дождаться восстановления
   объекта. Новый мир создаётся автоматически при заполнении.
3. Не увеличивать `WORLD_CAPACITY` без пересчёта нагрузки: это меняет лимиты
   мира и лобби.

## Вход не работает у всех

1. `/health` — жив ли Worker.
2. Проверить `JWT_SECRET` (длина ≥ 32) и `TURNSTILE_SECRET`/`TURNSTILE_SITE_KEY`.
3. Если задан секрет, но пуст site key — клиент не получит токен; задать ключ.
4. Проверить `auth_limits`: не стоит ли блокировка на общий IP (например, из-за
   прокси). Очистить конкретный ключ, не всю таблицу.

## Ошибка в деплое

1. Откатить предыдущий коммит (`wrangler rollback` или деплой прошлого тега).
2. Если менялись миграции D1 — не откатывать их слепо: сначала прочитать, какие
   таблицы затронуты.
3. После отката проверить Ledger и `jobs`.

## Реклама/платежи

На этапе 1 их нет. При подключении CryptoCoinsAd: отдельный флаг, отдельный CSP,
отключение без выпуска клиента.

## Контакты и след

Каждый инцидент: дата, версия, первый плохой `seq`/`job id`, что сделали, чем
проверили. Хранить рядом с журналом деплоев.
