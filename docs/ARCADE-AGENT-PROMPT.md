# Промпт для исполнителя: выложить аркаду в прод и проверить её живьём

Короткий текст для вставки агенту, у которого есть доступ к аккаунту Cloudflare и
к репозиторию. Сам раздел описан в `docs/ARCADE.md`, маршруты — в `docs/API.md`.
Этот файл отправляется целиком, без правок.

Главное, что нужно понять до начала: **миграций D1 для аркады нет**. Таблицы
`arcade_runs`, `arcade_daily` и `arcade_awards` живут в SQLite Durable Object
(`world/modules/arcade.ts` через `worker/src/world/schema.ts`, все `IF NOT EXISTS`)
и создаются сами при первом обращении к миру. `worker/schema/world/017_arcade.sql`
— справочное зеркало, `wrangler d1 migrations apply` его не видит и не должен.
Единственное обязательное действие — redeploy воркера: клиент (кнопки, экран,
39 PNG, `arcade-sim.js`) вшит в воркер, поэтому без сборки аркада в браузере не
появится.

~~~~text
Ты — инженер с доступом к моему аккаунту Cloudflare и к машине, где есть git,
node 20+ и терминал. Задача: выложить аркаду (десять мини-игр, этап 18) в прод и
доказать, что она работает у живого игрока. Денег не тратить, секреты не печатать.

РЕПОЗИТОРИЙ: github.com/alibahsburiev20-cyber/Crypto-Astra, ветка main.
ПРОД: https://crypto-astra.cryptoastra.workers.dev
D1: astra-global (прод), astra-preview (превью). Worker: crypto-astra.
Документация раздела: docs/ARCADE.md (правила десяти игр, награды, античит),
docs/API.md (три маршрута: GET /arcade, POST /arcade/start, POST /arcade/finish).

ЧТО УЖЕ СДЕЛАНО (проверено в CI, трогать не нужно):
- Игровой код в main, слияние PR #90 (коммит merge «Аркада: десять мини-игр…»):
  worker/src/shared/arcade.ts, worker/src/world/modules/arcade.ts,
  client/app.js + styles.css + index.html, 39 PNG, схема DO-мира.
- На PR #90 (сама аркада) зелёные: 796 unit-тестов, 39 E2E, typecheck,
  client-sync. В этом PR — смоук `scripts/arcade-smoke.ts`, этот промт и 8
  тестов, которые не дадут им «усохнуть»: всего 804 unit-теста.
- Награды аркады — только опыт; ASTRA, цены и балансы существующих систем не
  менялись. Так и должно остаться.

ЖЁСТКИЕ ПРАВИЛА (нарушение = остановка и отчёт мне):
1. Никаких миграций и CREATE TABLE руками ради аркады. Таблицы мира создаёт код.
   `wrangler d1 migrations apply` запускается только если ты нашёл несоответствие
   в d1_migrations — тогда сначала спроси меня.
2. Не начислять XP, ASTRA и очки вручную (ни в D1, ни в SQLite мира). Награда
   обязана прийти только из POST /arcade/finish.
3. Не включать и не выключать флаги экономики и платежей (PAYOUTS_ENABLED,
   SWEEP_ENABLED, POOL_ENABLED, PAY_*). Аркада к ним отношения не имеет.
4. Секреты не печатать, не пересылать в чат, не коммитить.
5. Тестовый игрок на проде — ОДИН, не больше: регистрация проверяет почту (MX) и
   считает регистрации с домена. Повторные регистрации = too_many_signup_from_domain.
6. Проверка не сошлась → стоп, отчёт мне, а не «починить наугад».

ШАГ 0. Окружение
  git clone https://github.com/alibahsburiev20-cyber/Crypto-Astra && cd Crypto-Astra
  git checkout main && git pull
  npm ci
  export CLOUDFLARE_API_TOKEN=...   # Workers Scripts: Edit, D1: Edit, Observability: Read
  export CLOUDFLARE_ACCOUNT_ID=...
  npx wrangler whoami
Если `wrangler whoami` не залогинен — остановись и напиши мне, обходить это
через дашборд и ручные правки таблицы нельзя.

ШАГ 1. Локальная зелёность до деплоя
  npm run check            # typecheck + typecheck:scripts + 804 unit-теста
  node scripts/embed-client.mjs && git diff --quiet worker/src/static/site.ts
Второе значит, что встроенный клиент не отстал от client/. Если diff не пуст —
пересобери (`npm run embed`) и сделай PR с пересборкой, в main молча не коммить.

ШАГ 2. Метка сборки
В wrangler.toml поле APP_BUILD (формат YYYY-MM-DD.N, например 2026-11-25.1) —
единственный способ отличить свежий прод от старого. Подними его сегодня. Это коммит в main
через PR: `git checkout -b chore/app-build-arcade`, правка, `npm run check`, push,
gh pr create → дождись CI → слей. Если правилу репозитория такой коммит не нужен
(скажи заранее) — правь на месте.

ШАГ 3. Деплой
  npm run deploy           # = node scripts/embed-client.mjs && wrangler deploy
Проверка:
  curl -s $BASE/health     # ok:true, build:<значение из шага 2>
Метка сборки обязана измениться. Не изменилась — деплой не прошёл, разбирайся.

ШАГ 4. Смоук аркады (главная проверка)
  npm run smoke:arcade -- --base $BASE --register --email <моя настоящая почта>
Скрипт делает ровно это и печатает построчно ok/FAIL:
  - GET /arcade → 10 игр, у каждой спрайт /sprites/arcade/<id>.png, все 200;
  - POST /arcade/start {game:"maze"} → runId + seed + runMs (с ключом Idempotency-Key);
  - заведомо читерский ввод (moves: [1,1,1,1,1]) → 409 bad_trace | too_fast | short;
  - тот же забег второй раз → 409 run_expired (забег закрыт, «пересдать» нельзя);
  - честный проход: путь считается тем же общим модулем → 200, очки > 0, win: true;
  - повтор ответа с тем же Idempotency-Key → байт в байт тот же ответ (нет двойного
    начисления);
  - /me: ASTRA до и после одинаковая, XP вырос ровно на начисленное;
  - /ledger: строки аркады есть и это только xp (ни astra, ни points);
  - endsAt = старт + runMs + 120 с grace (раунд живёт по серверному времени).
Код выхода 0 = всё сошлось. Любой FAIL → не «правь на проде», пиши мне точную
строку вывода.
Расход смоука: 2 попытки из суточных 10 у тестового аккаунта. Больше ничего он не
тратит и не меняет.

ШАГ 5. Проверка глазами (это и была жалоба владельца: «не могу открыть аркаду»)
Открой $BASE в браузере, войди тестовым игроком, нажми «Аркада» в сайдбаре (или в
нижней доке на телефоне). Ожидаешь:
  - заголовок «Десять мини-игр», 10 плиток с картинками, без пустых мест;
  - строка «попыток сегодня: N/10», счётчики побед и лучший счёт;
  - клик «Играть» → поле: canvas для лабиринта, DOM-сетка 9×9 для судоку, 20 карт
    для пар; сверху HUD с таймером, справа «Закончить»;
  - после сдачи — карточка с вердиктом сервера («Победа · N очков» или текст
    отказа) и строкой «Опыт: +N XP»;
  - консоль браузера без красных ошибок; сеть: /arcade 200, /arcade/start 200,
    /arcade/finish 200|409.
Если вместо каталога висит «Загружаем аркаду…» — это уже исправлено в main: должен
быть текст причины и кнопка «Повторить». Виснет — значит прод старше слияния,
вернись к шагу 3.

ШАГ 6. Состояние мира после прогонов (только чтение)
  curl -s -H "X-Admin-Token: $ADMIN_TOKEN" "$BASE/admin/world?world=<world_id>"
Значение ADMIN_TOKEN даю я, через переменную окружения; `npx wrangler secret list`
показывает только наличие секрета — значения он не печатает, и не должен.
Ответ даёт `frozen`, `verify { ok, rows, mismatches }` и `totals` (игроки, ASTRA,
очки, корабли, рейсы). Проверяешь три вещи:
  - frozen: false;
  - verify.ok: true и verify.mismatches: 0 — хеш-цепочка журнала цела после
    аркадных начислений;
  - totals.astra совпадает с тем, что было за минуту до шага 4 (сними его тем же
    запросом заранее). Аркада даёт опыт, а не эмиссию: если общий запас ASTRA
    сдвинулся не из-за чужих рейсов и боксов — стоп и пиши мне.
world_id тестового игрока — в ответе /auth/register или в /me (поле world_id).
Ни SELECT, ни правки в SQLite мира не нужны: аркада видна из /arcade и /ledger.

ШАГ 7. Превью-сборка (по желанию, но полезно перед следующим релизом)
Превью поднимает Cloudflare Builds автоматически на каждый PR: Cloudflare
dashboard → Workers → crypto-astra → Production → Previews → <имя ветки>. Прогони
на этом URL тот же смоук (`--base <preview-url>`) — тестовый аккаунт на превью
нужен свой, базы разные. Локально ещё проще:
  npm run dev &
  npm run smoke:arcade -- --base http://127.0.0.1:8787 --register --email t@example.com
astra-preview для аркады не мигрируется — см. правило 1.

ШАГ 8. Что зафиксировать
Впиши в docs/MONITORING.md строку «аркада: смоук <дата>, прод ok/FAIL, детали» и
в docs/ARCADE.md — если проверка вскрыла расхождение с документацией, правь документ
PR-ом, а не молча.

ЧЕГО НЕ ДЕЛАТЬ НИКОГДА:
- не создавать и не пересоздавать таблицы D1/мира, не писать в d1_migrations;
- не начислять награды руками, не «дописывать» строки в arcade_runs/arcade_daily;

7. Отрасли, где ты остановился и ждёшь меня: <...>
~~~~

## Если прод нужно откатить

`npx wrangler rollback` (или `npx wrangler deployments list` → откат на прошлый id).
Аркада безопасна в откате: её таблицы остаются в мире и никого не трогают, а
старый клиент просто не покажет раздел. Никаких данных игроков откат не затрагивает.

## Контекст, который не должен удивить

- Счёт всегда считает сервер: в теле `/arcade/finish` нет полей `score` и `win`,
  и клиентские тесты это сторожат. Если смоук показывает 200 с очками 600 — значит
  лабиринт реально пройден, а не «разрешён».
- Попытка сгорает на старте забега, поэтому «прощупать» маршрут десятью запусками
  нельзя: потолок 10 забегов в сутки (+4 Premium) и 200 XP в сутки на награды.
- Аркада не выдаёт ASTRA намеренно: экономика (боксы, рынок, рейсы, цены) тронута
  не была.
