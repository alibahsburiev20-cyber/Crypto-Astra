# Данные мира (Durable Object SQLite)

Один мир = один объект `World` = одна SQLite. Схема применяется при старте
объекта (`worker/src/world/schema.ts`, справочная копия — `worker/schema/world/`).

## Таблицы

| Таблица | Назначение |
|---|---|
| `meta` | служебные пары: `frozen`, `last_verify_at`, `last_verify_ok`, `frozen_seq` |
| `players` | `id`, `level`, `xp`, `guild_id`, `created_at` |
| `balances` | `astra`, `fuel`, `points`; `amount >= 0`; версия для будущих проверок |
| `ships` | `id`, `player_id`, `type`, `durability` 0…100, `status` |
| `resources` | добыча по видам, `amount >= 0` |
| `ledger` | журнал с хеш-цепочкой, append-only |
| `claim_state` | последний Claim, день, счётчик |
| `expeditions` | рейс: планета, тип, seed, время, статус, бонус события, износ, награда |
| `expedition_events` | события рейса: вид, окно, статус, выбор |
| `daily_counters` | рейсы, покупка топлива и очки по дням |
| `idempotency_keys` | ключи запросов и сохранённые ответы |
| `jobs` | отложенные задачи мира |
| `seasons` | сезоны: номер, рамки, статус, итоги закрытия |
| `season_results` | место, очки, уровень, опыт и приз каждого игрока в закрытом сезоне |
| `season_snapshots` | снимки мира для архива: sha256, голова цепочки, payload, отметка `exported` |
| `guilds` | гильдии: имя, тег, лидер, код приглашения (уникальный) |
| `guild_members` | состав: `guild_id`, `player_id`, роль `leader`/`officer`/`member` |
| `missions` | только отметки о выданной награде миссии (`player_id`, `period`, `mission_id`) |
| `referrals` | кто кого пригласил, когда приглашённый отлетал 5 рейсов и выдана ли награда |
| `achievements` | выданные бейджи: `player_id`, `achievement_id`, время |
| `pass_claims` | забранные уровни Astra Pass и награды за них |
| `box_state` | таймеры боксов: когда последний раз открыт и сколько раз |
| `box_opens` | журнал открытий: бокс, seed розыгрыша, цена, состав дропа |

## Инварианты

- `balances.amount >= 0`; уйти в минус нельзя, транзакция откатится.
- Любое изменение баланса идёт через `applyDelta`, которая пишет `ledger` в той же
  транзакции.
- `ledger` нельзя обновить или удалить (триггеры).
- Игрок не может иметь два активных рейса на одном корабле: проверка `ships.status`
  и `expeditions.status`.
- В мире не больше `WORLD_CAPACITY` (100) игроков.
- Все действия выполняются в `ctx.storage.transactionSync`; внешних `await`
  внутри транзакции нет.
- Активный сезон всегда один; очки — актив `points` в Ledger, а не отдельный
  счётчик. Закрытие сезона пишет призы и обнуление только через Ledger.
- Снимок уходит в архив только после отметки `exported`, которую ставит cron
  воркера после успешной записи в D1/R2.
- Прогресс миссий в таблицах не хранится: он пересчитывается по `expeditions`,
  `craft_jobs`, `market_sales` и `ledger`, поэтому накрутить его нельзя.
- `guild_members.player_id` — первичный ключ: игрок состоит максимум в одной
  гильдии, и `players.guild_id` дублирует это только для быстрых выборок.
- Награды Pass, миссий и рефералов идут через Ledger с `reason` `mission`,
  `pass`, `referral`; достижения баланс не меняют вовсе.
- Крафт пишется в `craft_jobs` (recipe, started_at, ends_at, fee) и журнал:
  входы списываются как `craft_input`, плата — `craft_fee`, выдача — `craft_output`.
  Рецепт берётся из `RECIPES`, поэтому новой таблицы для рецептов нет; у каждого
  рецепта есть `tier` — первый круг собирается из первого сектора, второй требует
  редких ресурсов, но новичку не нужен.
- Авиазвено (этап 6): `player_planes` хранит только счётчик машины на игрока
  (`player_id, plane, count, first_at, last_at`). Это не корабль и не актив:
  ячеек гаража не занимает, в `balances` и `ledger` не попадает — журнал
  отслеживает ASTRA, топливо, очки и ресурсы, а машина ни одного из них не даёт.
  Пропажа строки значит потерю косметики, но не расхождение сверки.
- Бокс: бесплатный ограничен таймером `box_state.last_open_at`, платный — ценой в
  ASTRA (`box_purchase`). Состав выпадает из seed, который сохраняется в
  `box_opens`, поэтому выдачу можно перепроверить, а клиент на неё не влияет.

## Что не хранится здесь

Аккаунты, сессии, места лобби — в D1. Мир ничего не знает про email и пароль,
кроме `player_id` (он же `users.id`).

## Миграция старой схемы рейсов

`migrateLegacyExpeditions` в `world/migrate.ts` при старте объекта находит таблицу
с колонкой `sector` и без `planet` (ранняя версия), возвращает топливо за активные
рейсы, снимает `away` с кораблей и пересоздаёт `expeditions` по текущей схеме.
Миграция идемпотентна и выполняется внутри транзакции до создания таблиц.

## Диагностика

Через Durable Object SQL (не D1):

```sql
SELECT * FROM meta;
SELECT player_id, asset, amount FROM balances WHERE amount < 0;
SELECT status, kind, COUNT(*) FROM jobs GROUP BY status, kind;
SELECT seq, hash, prev_hash FROM ledger ORDER BY seq DESC LIMIT 5;
```
