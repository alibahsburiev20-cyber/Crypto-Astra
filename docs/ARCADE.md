# Аркада: десять мини-игр (этап 18)

Один раздел, десять самостоятельных игр. Общее у них три вещи: поле строится из
серверного зерна, счёт считает сервер, награда — только опыт. Раздел открывается
из сайдбара и из ниж дока («Аркада»), живёт рядом с ареной и ничего у неё не
берёт, кроме привычных CSS-классов.

## Состав

| Игра | id | Тип | Механика | Раунд |
| --- | --- | --- | --- | --- |
| Кристальный блокпост | `maze` | логика | лабиринт из DFS-блоков, выйти кратчайшим путём | 180 с |
| Кубическая раскладка | `sudoku` | логика | судоку 9×9 с единственным решением | 600 с |
| Нейро-пары | `memory` | логика | 10 пар карт за минимум ходов | 240 с |
| Сигнальная цепь | `sequence` | логика | «Саймон»: повторить растущую последовательность | 180 с |
| Импульс | `reaction` | логика | восемь окон по 260 мс, важна задержка | 20 с |
| Обход пояса | `runner` | экшн | прыжок через валун, не прыжок под дрона | 30 с |
| Разбор щита | `breakout` | экшн | арканоид: платформа, заряд, 40 кирпичей | 60 с |
| Сборка зонда | `snake` | экшн | змейка 24×15, корм из зерна | 60 с |
| Снайперский полигон | `aim` | экшн | 14 целей-вспышек, промах стоит очков | 25 с |
| Грузовая сеть | `catch` | экшн | ловля груза на линии, обломки мимо | 45 с |

Идеи — общественное достояние жанра: лабиринт с генерацией DFS, судоку с
проверкой единственности решения, «Память», Simon, тест реакции, раннер,
Breakout, Snake, aim-trainer и «поймай падающий объект». Никаких чужих
ассетов и кода: рисует всё `scripts/build-sprites.sh`, логика написана в
`worker/src/shared/arcade.ts`.

## Как счёт нельзя накрутить

1. `POST /arcade/start` создаёт строку забега, выдаёт `seed` и дедлайн
   `endsAt = now + runMs + 120 с`. Зерно — `crypto.getRandomValues`, не время.
2. Клиент строит поле из зерна **тем же кодом**, что сервер, и собирает ввод:
   списки ходов (`moves`, `answers`, `presses`, `taps`, `shots`, `dirs`) или
   трассу (`axis` — координата ×10 по сетке `stepMs`).
3. `POST /arcade/finish` ничего не принимает «на веру»: `evaluateArcade(game,
   seed, input)` пересчитывает забег целиком и возвращает очки 0…600.
4. Отсекается всё, что противоречит правилам поля:
   - лабиринт — шаг сквозь стену и путь **короче** кратчайшего (BFS считается
     сервером; короче бывает только подбор по зерну);
   - судоку — правка подсказки и ответ, не совпадающий с единственным решением;
   - пары — повтор уже собранной или открытой карты;
   - цепь — засчитывается только префикс до первой ошибки;
   - реакция и снайпер — тапы чаще 150/120 мс и списки длиннее `окон + 2`
     (`too_fast`, `bad_trace`): «зажать клавишу» не конвертируется в очки;
   - экшн-игры — `readAxis` зажимает координаты в поле и скорость в физический
     предел, поэтому телепорт превращается в «игрок не успел приехать».
5. Кривой ввод сжигает попытку и не даёт награды — иначе по ней можно было бы
   перебирать ответы бесплатно. Попытка возвращается только на следующий день.
6. Повтор `finish` с тем же `Idempotency-Key` отдаёт сохранённый ответ; с другим
   телом — `idempotency_key_reused` (409). Просроченные забеги закрывает
   `expireStale` при следующем обращении.

Симуляции `breakout` и `snake` сервер пересчитывает сам (`stepBreakout`,
`stepSnake`), поэтому «сколько разбилось» и «сколько съедено» — тоже не слово
клиента. Клиент ведёт локальную картинку по тем же функциям, и тест
`arcadeLogic.test.ts` сверяет разрушенные кирпичи с серверным `detail`: расхождение
в физике ловится сразу.

## Награды и почему они такие

| За что | Сколько |
| --- | --- |
| Зачтённый забег | `3 + ⌊очки/100⌋ × 3 + 6 за победу` XP, то есть 3…27 XP |
| Суточный потолок опыта | 200 XP на весь раздел |
| Попытки | 10 в сутки на все десять игр, Premium +4 |
| Медали побед | 10 / 30 / 75 побед → +60 / +150 / +300 XP, одна разово |
| «Десять игр — десять побед» | победа в каждой игре каталога → +200 XP, разово |
| Неделя в аркаде | 15 побед за календарную неделю (UTC) → +120 XP, раз в неделю |

ASTRA, очки сезона и ресурсы аркада **не начисляет и не списывает** — ни за
забег, ни за медаль, ни за недельную цель. Это осознанно: десять новых игр с
валютой легко перетянули бы экономику на себя, а ограничение «экономику не
трогать» для этого этапа важнее красивых наград. Единственный ресурс, который
растёт, — опыт: он ничего не стоит и только снимает замки уровня (секторы,
верфь). Суточный потолок опыта нужен, чтобы десять игр не сложились в
бесконечный гринд уровня: 200 XP — это примерно восемь идеальных забегов.

Потолок считается по фактически выданному (`arcade_daily.xp`), а не по «сколько
могли бы»: забег при выбранном потолке всё равно засчитывается в статистику и
в медали, просто без XP. Отказ «попыток нет» не запоминается в
идемпотентности, поэтому через сутки тот же ключ пройдёт.

## Экран

- Каталог: десять плиток со спрайтом, правилами, управлением, лучшим счётом и
  числом побед. Кнопка «Играть» гаснет, когда пул попыток выбран.
- Сцена: canvas 1000×620 для `maze`, `reaction` и пяти экшн-игр; DOM-поле для
  `sudoku`, `memory` и `sequence`. Над полем — HUD (таймер раунда и живой счёт),
  справа — кнопка «Закончить»; живой счёт показывает ход игры, но итог всё
  равно за сервером.
- Итог забега: карточка с очками и разбором («шагов 50 из 50», начисленным
  опытом и выданными медалями. Отказ — тот же текст, что у арены
  (`bad_trace`, `too_fast`, `short`, `run_expired`).
- Блоки: медали, недельная цель, последние забеги, лидерборд аркады
  (`arcadeLeaderboard` — отдельный от арены, чтобы два рейтинга не смешивались).
- Разметка собирается через `el()` и `textContent`: данные (позывные из
  лидерборда, подписи медалей) не попадают в HTML-строку — правило клиента
  проверяет `arcadeUi.test.ts`.
- Звук — тот же синтезированный `sfx()` и общий переключатель `astra:sound`.
- Раздел грузится одним запросом. Если `/arcade` не ответил, экран не зависает в
  «Загружаем аркаду…»: показывается причина (текст из `ERRORS`) и кнопка
  «Повторить». Флаг `arcadeLoading` нужен, чтобы ошибка не запускала цикл
  «render → loadArcade → ошибка → render»: без него клиент долбил бы сервер без
  паузы. Тот же дефект убран и в «Арене» (`loadArena`).
- Полосы ступеней медалей считаются от побед игрока (`a.wins`), а не от порога
  ступени — иначе они были бы заполнены у новичка.

## Арт

39 PNG: 10 плиток каталога (`/sprites/arcade/<id>.png` — имя равно id игры),
`wall`/`exit`/`cell` для лабиринта, `card_back`/`card_open` и десять «рубашек»
для пар, четыре узла цепи, маяк, детали раннера (`rock`, `drone`, `gem`,
`runner_hero`), арканоида (`ball`, `brick`, `paddle`), змейки
(`snake_head`, `snake_body`, `food`), мишень, ловушка (`hook`, `crate`,
`debris`), пять медалей и фон `/sprites/bg/arcade.png`. Всё рисуется
`scripts/build-sprites.sh`, SVG нет, каждый файл <400 КБ.

Живой воркер (dev, превью или прод) проверяется одним прогоном:

```bash
npm run smoke:arcade -- --base http://127.0.0.1:8787 --register --email t@example.com
npm run smoke:arcade -- --base https://<домен> --email … --password …
```

`scripts/arcade-smoke.ts` проходит полный круг и печатает построчно `ok`/`FAIL`:
каталог из десяти игр и все десять спрайтов, `409 bad_trace` на ход сквозь стену,
`409 run_expired` на повторную сдачу, честный лабиринт (200, очки, `win`), побитово
совпадающий повтор с тем же `Idempotency-Key`, неизменный баланс ASTRA и
`reason: 'arcade'` в журнале. Расход — 2 попытки из суточных 10 у тестового
аккаунта. Для исполнителя с доступом к Cloudflare это же расписано по шагам в
`docs/ARCADE-AGENT-PROMPT.md`.

Пересборка после правок в `worker/src/shared/arcade.ts`:

```bash
npm run build:arcade   # → client/arcade-sim.js
npm run embed          # → worker/src/static/site.ts (статика клиента)
```
