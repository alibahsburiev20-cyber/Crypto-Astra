# Astra Pay Signer: как включить

Signer — отдельный Worker, в котором живут ключи. Основной Worker ключей не
знает: он просит адрес и подпись, а получает только результат.

## Состояние на 17 ноября 2026

Приём USDT и покупки **включены** (`PAYMENTS_ENABLED`, `DEPOSITS_ENABLED`,
`PURCHASES_ENABLED` = `on`), сеть — `mainnet`. Осталось одно: Signer.

Пока он не настроен, `/pay/status.json` отдаёт `wallets: "signer_required"`,
`/pay/address.json` — `503 signer_not_configured`, а витрина показывает
«Нужен кошелёк» вместо кнопки покупки. Деньги при этом никуда не уходят:
без адреса игрок физически не может отправить USDT.

## Что нужно один раз

1. **Создать Worker.** Dashboard → Workers & Pages → Create → Worker →
   имя `astra-pay-signer` → Deploy. Код подтянется из репозитория, если
   подключить его как отдельный проект (`signer/wrangler.toml`).

2. **Задать три секрета.** Dashboard → Workers → `astra-pay-signer` →
   Settings → Variables and Secrets → *Encrypt*:

   | Имя | Значение |
   |---|---|
   | `SIGNER_TOKEN` | случайная строка ≥ 32 символов (например, сгенерируйте в браузере) |
   | `SIGNER_SEED` | 64 hex-символа (32 байта). **Один раз и навсегда**: из него выводятся адреса игроков |
   | `SIGNER_PRIVATE_KEY` | 64 hex-символа — приватный ключ горячего кошелька, с которого уходят выплаты |

   `SIGNER_SEED` и `SIGNER_PRIVATE_KEY` не попадают в репозиторий, D1, браузер
   и `[vars]`. Резервная копия семени — на бумаге, не в облаке.

3. **Связать Workers.** В корневом `wrangler.toml` раскомментировать:

   ```toml
   [[services]]
   binding = "SIGNER"
   service = "astra-pay-signer"
   ```

   и добавить в основной Worker секреты `SIGNER_TOKEN` (тот же) и
   `PAY_HOT_ADDRESS` (публичный адрес горячего кошелька).

4. **Проверить.** `GET /pay/address.json` с токеном игрока должен вернуть `T…`.
   Повторный вызов — тот же адрес.

## Горячий кошелёк: откуда взять ключ с телефона

Нужны **64 hex-символа** — приватный ключ TRON-адреса, с которого уходят выплаты.
Мнемоника (12 слов) Signer не подходит: он принимает именно hex-ключ.

1. **Отдельный кошелёк, не основной.** Trust Wallet → «+» (или переключатель
   кошельков) → *Create a new wallet* → сохранить 12 слов на бумаге. Этот кошелёк
   будет только для выплат.
2. В нём → **Receive** → выбрать **TRON** → скопировать адрес (`T…`).
3. В нём → **Settings / ⋯ → Show Secret Phrase** → выбрать **Private Key**
   для TRON (приложение спросит пароль). Это и есть ключ: 64 hex-символа.
4. Dashboard Cloudflare → Workers & Pages → `astra-pay-signer` → Settings →
   Variables and Secrets → *Add* → тип **Secret** → имя `SIGNER_PRIVATE_KEY` →
   вставить ключ → Save.
5. В основном Worker (`crypto-astra`) тем же способом задать `PAY_HOT_ADDRESS` =
   адрес из шага 2. **Адрес и ключ должны быть от одного кошелька** — иначе сеть
   отклонит подпись, и это будет выглядеть как «выплата не ушла».

Проверка без ключа: сравнить адрес, который показывает Trust Wallet, с тем, что
задан в `PAY_HOT_ADDRESS` (посимвольно) — этого достаточно. Если ключ уже вписан,
но адрес выглядит чужим, `scripts/hot-address.ts --check T…` покажет, совпадают ли
они, не выводя сам ключ.

Почему отдельный кошелёк: ключ живёт в секрете Worker и попадает в логи при
ошибке настройки. На отдельном кошельке лежит только операционный остаток, а не
всё, что у тебя есть.

## Комиссия

Перевод TRC-20 без энергии сжигает ~15 TRX (`SWEEP_FEE_SUN`). Если TRX нет,
перевод не пройдёт — даже когда USDT на кошельке есть. Проверка стоит перед
подписью: `POST /admin/pay/send` отвечает `409 hot_wallet_insufficient_usdt` или
`409 hot_wallet_no_trx` с точной нехваткой, а заявка остаётся `reserved`
(деньги с баланса игрока списаны и не потеряны).

Если найдётся человек с TRX, он может **делегировать энергию** на этот адрес —
тогда комиссию платит его стейк, а твой TRX не расходуется.

## Что Signer проверяет перед подписью

- `sha256(raw_data) === txID` — тело не подменили по дороге;
- в теле есть адрес получателя из запроса (32-байтный слот);
- в теле есть ровно эта сумма;
- сумма не больше `SIGNER_MAX_TX_MICRO` (по умолчанию 100 USDT);
- адрес получателя проходит контрольную сумму base58check.

Не совпало — отказ. Каждая подпись пишется в логи Worker: `txID`, получатель,
сумма, без ключей.

## Чего Signer не делает

- Не хранит приватные ключи в D1 и не отдаёт их по API.
- Не публикуется в интернет: `workers_dev = false`, доступ только по binding.
- Не заменяет мультисиг. Для mainnet правильный путь — 2-из-3 on-chain:
  ключ в Cloudflare остаётся одним из трёх, а не единственным.
