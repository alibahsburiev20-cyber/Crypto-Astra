# Этап 3 «Сезоны»

Основание: спецификация 2.1, §II.6 (задачи `season_close`, `snapshot_export`),
§II.10 (сезоны), часть V (гейт 3). Правила для игрока — `docs/SEASON.md`.

Цель этапа: дать миру причину возвращаться — сезон на восемь недель с рейтингом,
наградами и закрытием, — и научиться сохранять историю так, чтобы её можно было
проверить и восстановить.

Работа идёт срезами; каждый срез — рабочий код с тестами.

## Срез 1. Сезон и рейтинг

- Таблицы мира: `seasons`, `season_results`, `season_snapshots` (схема стартует
  вместе с объектом, мир не требует миграции данных).
- `ensureSeason` создаёт первый сезон при первом же обслуживании мира и не
  плодит дубликаты. Пропущенные сезоны не догоняются.
- Рейтинг считается по балансу `points`, а не отдельным счётчиком: очки и так
  живут в Ledger, поэтому подделать их из клиента нельзя, а сверка их проверяет.
- Тай-брейк: очки → опыт → дата регистрации → id.
- `/me` получает компактный блок `season`, `GET /season` — полный отчёт (топ-20,
  призы, прошлые сезоны).

Критерий выполнен: 15 unit-тестов на рамки, рейтинг, тай-брейк и отчёт;
e2e проверяет `/season` и отказ гостю.

## Срез 2. Закрытие сезона и призы

- Задача `season_close` ставится на `ends_at` при создании сезона и повторно —
  на следующий сезон после закрытия.
- `closeSeason` в одной транзакции: пишет `season_results`, начисляет призы
  (`season_reward`), обнуляет очки (`season_reset`), закрывает сезон и открывает
  следующий.
- Замороженный мир призы не получает: задача переносится на час. Это защита от
  выпуска ASTRA по журналу, которому нельзя верить.
- Повторное закрытие идемпотентно по статусу сезона.
- Симуляция `--season --days 56 --mix`: призы 1.7 % выпуска, поглощение 81.8 %
  (цель 70–90 %).

Критерий выполнен: призы и обнуление видны в Ledger, `verifyLedger` зелёный,
закрытие по задаче снимает снимок с итогами.

## Срез 3. Снимки, архив и восстановление

- `snapshot_export` раз в неделю и сразу после закрытия сезона складывает
  компактный JSON в `season_snapshots` мира: суммы, голова хеш-цепочки, результат
  сверки, для закрытия — итоговая таблица.
- Cron воркера (`syncArchive`) забирает снимки, кладёт в R2 (если бакет
  подключён) или в D1 `world_snapshots`, дублирует итоги сезона в D1
  `season_history` и только после успешной записи ставит отметку `exported`.
- Миграция D1 `0005_season_archive.sql`; бакет R2 необязателен и включается
  блоком `[[r2_buckets]]`, когда появится доход.
- `npm run verify-snapshot` проверяет снимок из архива: формат, суммы, голову
  цепочки, призы; `--sha256` сверяет файл с хешем из D1.

Критерий выполнен: 5 тестов проверки снимка, 3 теста строки истории D1, в мире
снимок уходит из очереди только после подтверждения.

## Гейт 3

| Требование | Статус |
|---|---|
| Симуляция в норме | ✅ 8 недель, 200 игроков, смешанная популяция: 83.2 % без призов, 81.8 % с призами |
| Первый сезон закрывается без ручных правок Ledger | ✅ закрытие идемпотентно, призы и обнуление идут только через Ledger, `verifyLedger` зелёный |
| Архив и проверка восстановления | ✅ снимок в D1/R2 + `npm run verify-snapshot`; полное восстановление — по `RUNBOOK_BACKUP.md` |

Оговорка: «первый сезон закрыт» на живом мире наступит через 8 недель после
старта. Код к этому готов, симуляция и тесты закрывают логику; сам факт закрытия
на проде — наблюдение, а не задача разработки.

## Что осталось за этапом

- Astra Pass (второй слот крафта) и косметика — этап 4–5, после юриста.
- Пул и выплаты — только после гейта 4.
- R2 включается вместе с бакетом; до этого архив живёт в D1.
