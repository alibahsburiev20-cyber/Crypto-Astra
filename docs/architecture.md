# Crypto Astra — архитектура v1

## Границы доверия

### Браузер
Отвечает за интерфейс и отображение данных. Клиентские значения можно подделать, поэтому браузеру нельзя доверять при расчёте баланса, стоимости покупки, длительности экспедиции, наград или долей пула.

### Cloudflare Worker
Единственная точка для критичных игровых команд:
- проверяет Supabase access token;
- проверяет Turnstile token там, где требуется антибот-защита;
- проверяет входные данные и ограничения частоты запросов;
- вычисляет стоимость, расход топлива, время завершения и награды;
- выполняет атомарные изменения через защищённый серверный доступ к Supabase;
- записывает каждую операцию в ledger с уникальным idempotency key.

### Supabase
- Auth — учётные записи и сессии;
- Postgres — состояние игры;
- RLS — изоляция пользовательских данных;
- серверный доступ — только из Worker через секрет.

## Правила безопасности

1. Запретить клиенту напрямую изменять баланс и ledger.
2. Не принимать цену, награду, завершение таймера или долю пула от клиента.
3. Использовать серверное время UTC.
4. Применять уникальный ключ операции для защиты от повторного запроса.
5. Включить RLS на всех таблицах в exposed schema.
6. Не помещать service role key, Turnstile secret или payout API key во frontend или Git.
7. Для выплат вести отдельный ledger, проверку доступного баланса и статус провайдера.
8. Не запускать реальные выплаты до проверки личности, возраста, региона, правил провайдера и юридических требований.

## Демо-ограничение

Текущие `app.js` и `styles.css` — прототип интерфейса. Демо-операции не являются безопасной игровой экономикой и не должны использоваться для денежных наград.
