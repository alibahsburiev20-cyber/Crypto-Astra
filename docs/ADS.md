# Реклама: оценка сети и план интеграции

Проверено 18.11.2026 по просьбе владельца: `cryptocoinsad.com`.

## Что это

Селф-серв рекламная сеть для крипто-трафика (контакт — Кипр, `contact@cryptocoinsad.com`,
кабинет на `app.cryptocoinsad.com`). Рекламодатели платят криптой от $1, паблишеры
получают выплаты в крипте, минимальный вывод по отзывам 2026 года — $10.

Форматы, которые они предлагают паблишерам:

| Формат | Что это | Годится игре? |
|--------|---------|----------------|
| Text Ads | строка 40 символов + описание 50 | нет, некуда вставить |
| Banner Ads | 728×90, 300×250, 160×600, 468×60, 320×100; JPG/PNG/GIF/HTML5/MP4/WebM | только как спонсорский слот |
| Pop-Under | открывает вкладку при клике по странице | нет: ломает игру и раздражает |

## Чего у них нет

- **Rewarded video SDK.** «Video banners» — это видео-креатив внутри баннера, а не
  формат «посмотрел ролик до конца — получил награду». Скрипта, который можно
  встроить в игру и получить событие `completed`, у них не заявлено.
- **Server-to-server postback.** Награду в Ledger нельзя начислить по их сигналу;
  только по нашей собственной кнопке, что открывает дыру для накрутки.
- **Публичных требований и оферты.** `/publishers`, `/faq`, `/?p=terms` отдают 404 —
  условия можно узнать только после регистрации в кабинете.

## Репутация

Trustpilot по региональным доменам расходится: 4.3 (10 отзывов), 3.4 (7), 2.9 (6).
Есть повторяющаяся жалоба: «выплатили три раза, потом подняли минималку, через три
месяца деактивировали аккаунт без причины» (июль 2024). Часть пятизвёздочных отзывов
явно накручена — один из них состоит из SEO-спама со ссылками. Компания отвечает на
негатив, но ответы шаблонные.

Вывод: как эксперимент на малом объёме — допустимо, как единственный источник дохода
и как основание для гейта — нет.

## Что это значит для гейта 2

Формулировку «отчёты провайдера сверены + письменное подтверждение CryptoCoinsAd»
нужно менять: rewarded-модель с этой сетью не реализуема, а сверять отчёты по баннерам
имеет смысл только когда есть показы.

Предлагаемая формулировка гейта 2:

- рекламный модуль существует и выключен флагом `ADS_ENABLED`;
- начисление награды за просмотр идемпотентно и пишется в Ledger;
- есть адаптер под сеть и скрипт сверки «их отчёт против наших начислений»;
- живого контракта и сверки нет — это шаг после набора трафика (гейт 3).

## План в коде (этап 2)

1. `worker/src/ads/` — адаптер с двумя реализациями: `banner` (iframe/img слот,
   размеры 728×90 и 300×250) и `rewarded` (заглушка до появления SDK).
2. Слот в клиенте: полоса под топбаром или в подвале панели, `loading="lazy"`,
   отключается на мобиле тоньше 380 px.
3. CSP: отдельная директива для домена сети, как уже записано в `docs/SECURITY.md`.
4. Начисление: `POST /ads/reward` с `Idempotency-Key`, лимит 3 просмотра в сутки,
   запись `reason: 'ads_reward'` в Ledger, отчёт `npm run ads-report`.
5. Флаг в `wrangler.toml`, по умолчанию `false` — в проде реклама не показывается,
   пока нет договора.

## Что спросить у сети перед подключением

1. Есть ли rewarded video SDK для браузерных игр и событие «просмотр завершён»?
2. Есть ли S2S postback и как он подписывается?
3. Принимаете ли игровые сайты (не только крипто-новости), какой минимум трафика?
4. Какая политика деактивации аккаунта и что происходит с невыплаченным балансом?
5. Нужен ли KYC и какие налоговые документы для резидента ЕС?
6. Ставки CPM/CPC по гео DE/RU/CIS и fill rate по ним.
